# اجرای مرحله زیرساخت — ۱۹ نوامبر ۲۰۲۶

## بهینه‌سازی کلیدهای خارجی دیتابیس

- Migration با نسخه `20261119094914` و نام `kaveh_fk_covering_indexes` روی Supabase Production با موفقیت اجرا شد.
- ده index برای ستون‌های Foreign Key که Performance Advisor گزارش کرده بود اضافه شدند.
- بررسی مستقیم `pg_indexes` وجود هر ده index را تأیید کرد.
- هیچ جدول، policy، رکورد کاربر یا فایل حذف یا بازنویسی نشد.
- پس از افزودن indexها، هشدار `unindexed_foreign_keys` دیگر در Performance Advisor دیده نشد.
- Advisor اکنون indexهای تازه را به‌عنوان `unused_index` با سطح INFO فهرست می‌کند؛ این رفتار بلافاصله پس از ساخت index طبیعی است و به‌معنای خطای ساخت نیست. هیچ index موجودی برای خاموش‌کردن این هشدار حذف نشد.

## وضعیت امنیت و موانع باقی‌مانده

- Supabase همچنان `ACTIVE_HEALTHY` است.
- هشدار امنیتی `auth_leaked_password_protection` همچنان فعال است. این گزینه باید از تنظیمات Auth داشبورد Supabase فعال شود؛ با Migration دیتابیس قابل جایگزینی نیست.
- Performance Advisor همچنان ۷ هشدار `multiple_permissive_policies` دارد. این policyها باید موردی از نظر منطق دسترسی بررسی شوند؛ ادغام کورکورانه می‌تواند دسترسی اعضای گروه/کانال یا فایل‌های اشتراکی را خراب کند.
- محدودیت MIME در دو Storage bucket هنوز تنظیم نشده است. پیش از تغییر آن باید با فهرست انواع فایل‌های واقعاً پشتیبانی‌شده در وب و Android تطبیق داده شود تا آپلودهای فعلی ناگهان از کار نیفتند.
- این مرحله تغییر UI یا انتشار وب ندارد؛ تغییر دیتابیس در Production اعمال شده و فایل Migration و مستندات در مخزن ثبت شده‌اند.

## گام بعدی

1. بررسی و اصلاح هدفمند policyهای چندگانه همراه با تست دسترسی مالک/عضو/غیرعضو.
2. تکمیل allowlist فایل‌ها در کلاینت‌ها و Storage، بدون اجازه‌دادن به HTML/SVG/فایل اجرایی.
3. پیگیری فعال‌سازی leaked-password protection از داشبورد Supabase.
4. تست End-to-End ثبت‌نام ایمیلی، تنظیم رمز، خروج، ورود با رمز و حفظ نشست در وب و Android.
